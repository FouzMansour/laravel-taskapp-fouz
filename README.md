# Laravel Task Manager

A small Laravel app where a **manager** assigns tasks to **employees**, employees mark them complete, and the manager approves or rejects the result.

Built with Laravel 13, Blade, Breeze (login only), Laravel Reverb, SQLite, and Pest.

> Reverb is used for the realtime notifications requirement of this exercise. It is the only package added beyond Breeze.

## Roles and rules

- **Manager:** sees all tasks, creates and assigns tasks, edits/deletes tasks while `pending`, approves or rejects `completed` tasks (a note is required on reject).
- **Employee:** sees only their own tasks, marks them complete when `pending` or `rejected`.
- Task lifecycle: `pending` -> `completed` -> `approved` (final) or `rejected` -> `completed` again.
- Forbidden actions return a 403 page. All rules live in `app/Policies/TaskPolicy.php`.

## Localization

- Supports Arabic and English.
- Users can switch languages using the language selector in the navigation bar.
- The interface direction changes automatically: RTL for Arabic and LTR for English.
- Notification messages are translated according to the recipient's currently selected language.
- Notifications store translation keys instead of pre-translated messages, allowing them to be displayed in the selected language.

## Realtime notifications

Realtime notifications use Laravel Reverb, Laravel Notifications, and Laravel Echo. Users receive them without refreshing the page.

### Notification events

| Event                              | Who is notified            |
| ---------------------------------- | -------------------------- |
| Manager creates and assigns a task | The assigned employee      |
| Employee completes a task          | The manager who created it |
| Manager approves a task            | The assigned employee      |
| Manager rejects a task             | The assigned employee      |

### Notification features

- Realtime delivery over WebSockets (private channel `App.Models.User.{id}`).
- Notifications are also stored in the database (`notifications` table).
- If the user was offline, unread notifications appear in a banner the next time they open the app.
- A notification is marked as read when it arrives live, or when the user opens the related task.
- Each notification links to its task.
- Notification messages support Arabic and English and are translated according to the recipient's selected language.

### Live updates

The tasks list and the task page update automatically when a task changes (created, edited, deleted, completed, approved, rejected), without a page reload. This uses a broadcast event (`TaskUpdated`) on the private channel `tasks.{userId}`, and Laravel Echo in the browser.

## Requirements

- PHP 8.3 or newer
- Composer
- Node.js 20 or newer

## Setup

```bash
git clone <repo-url> laravel-taskapp
cd laravel-taskapp

composer install
npm install
npm run build

cp .env.example .env
php artisan key:generate

touch database/database.sqlite
php artisan migrate:fresh --seed
```

### Environment variables

Make sure `.env` contains:

```env
BROADCAST_CONNECTION=reverb
QUEUE_CONNECTION=database
```

The `REVERB_*` and `VITE_REVERB_*` values are generated by:

```bash
php artisan install:broadcasting --reverb
```

If they are missing in your `.env`, run that command (answer "No" if it asks to overwrite existing files), then:

```bash
php artisan config:clear
npm run build
```

## Run

Open three terminals in the project folder and keep them running:

```bash
php artisan reverb:start
```

```bash
php artisan queue:work
```

```bash
npm run dev
```

- `reverb:start`: WebSocket server that pushes events to the browser.
- `queue:work`: delivers notifications in the background. Without it, notifications are not sent.
- `npm run dev`: builds the JS (not needed if you already ran `npm run build`).

Then open http://localhost:8000 (if you use `composer run dev`) or your Herd URL, e.g. http://taskapp.test.

## How to try the realtime features

1. Log in as `manager@example.com` in a normal window.
2. Log in as `ali@example.com` in an incognito window and stay on `/tasks`.
3. As the manager, create a task for Ali: Ali sees a notification and the new task in his list instantly.
4. As Ali, mark it complete: the manager gets a notification and sees the status change.
5. Close Ali's window, create another task, then open Ali again: the notification appears in the banner.

## Tests

```bash
php artisan test
```

The feature tests are in `tests/Feature/TaskTest.php`. Notifications and broadcast events are faked, so Reverb does not need to be running to run the tests. The registration tests that came with Breeze are skipped because registration is disabled.

## Project structure (main files)

- `app/Enums/TaskStatus.php`: the four task statuses
- `app/Models/Task.php`, `app/Models/User.php`: models and relationships
- `app/Policies/TaskPolicy.php`: all authorization rules
- `app/Http/Controllers/TaskController.php`: task CRUD
- `app/Http/Controllers/TaskStatusController.php`: complete, approve, reject
- `app/Http/Requests/`: form validation
- `app/Notifications/TaskNotification.php`: database and broadcast notification
- `app/Events/TaskUpdated.php`: broadcast event for live list/page updates
- `app/Http/Middleware/SetLocale.php`: sets the active language from the session
- `lang/ar.json`, `lang/en.json`: Arabic and English translation strings
- `routes/channels.php`: private channel authorization
- `routes/web.php`: routes, including the notification read endpoint
- `resources/views/tasks/`: Blade views
- `resources/views/layouts/app.blade.php`: Echo listeners and unread banner
- `resources/views/layouts/navigation.blade.php`: navigation menu and language selector
